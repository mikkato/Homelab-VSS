## 2.1.7 (vc 29) — падение при сбое DNS, доступ к crash-дампам, Keystore
- Падение найдено живьём: UnknownHostException (DNS не разрешился — сеть
  отвалилась) пробрасывался из HTTP-слоя в main и валил приложение. Все
  сетевые ошибки OkHttp свёрнуты в штатную FrigateApiException — показ
  «Нет связи» вместо падения.
- SettingsStore: при битом ключе Android Keystore восстановление удаляло
  неверный алиас — битый ключ оставался, повторное создание хранилища снова
  бросало, и приложение падало на каждом обращении к настройкам. Теперь
  удаляется реальный алиас MasterKey; при двойном провале — фолбэк на
  обычные SharedPreferences вместо падения.
- После любого падения баннер со стеком виден прямо на главном экране и в
  Настройках; полный дамп — в Логи → «Приложение» (читается без сервера).

## 2.1.6 (vc 27) — детекция не молчит при пустом списке объектов
При включении detect приложение проверяет objects.track на сервере и
предупреждает: при пустом списке отслеживаемых объектов Frigate детекцию
ведёт, но объекты не ищет — детекций не будет, как бы ни был включён свитч.

## 2.1.5 (vc 26) — «поток завис» видно и лечится с плитки
Frigate иногда теряет захват камеры (камера жива, по тапу видео есть, а
миниатюра показывает серверную заглушку «No frames have been received»).
Теперь:
- Live читает /api/stats; при camera_fps=0 плитка показывает оверлей
  «Поток завис на сервере — Оживить» вместо непонятной заглушки;
- тап «Оживить» → подтверждение → рестарт Frigate → приложение само ждёт
  возврата потока (до ~80 с) и снимает оверлей.

## 2.1.4 (vc 25) — кнопка «Перезапустить Frigate» на экране Камеры
После смены detect/record (применяются Frigate только после перезапуска)
внизу списка камер появляется кнопка «Перезапустить Frigate» с подтверждением —
больше не нужно искать рестарт в общих настройках. После рестарта показывается
подтверждение, что изменения применятся через минуту.

## 2.1.3 (vc 24) — фикс «Не сохранено: ?» в разделе Камеры
Кнопка «Сохранить» на экране камер (и «Сохранить» на экране объектов) вызывала
`POST /api/config/save`, который в Frigate 0.17 требует query-параметр `save_option`
и raw-YAML тело — сервер отвечал 400 вне известного маппинга, отсюда
«Не сохранено: ?». Само изменение к тому моменту уже сохранено на сервере
(`config/set` в 0.17 сам пишет config.yml), поэтому кнопка убрана:
- свитчи detect/record пишут конфиг сразу и показывают «Сохранено» + подсказку
  про перезапуск Frigate (эти параметры применяются после рестарта);
- свитч enabled камеры — через live-топик, применяется без рестарта;
- ошибки свитчей теперь показываются по-русски (раньше глотались молча).

## 2.1.2 (vc 23) — корректное отключение тревог и уведомлений
Полностью переработан путь «выключил — не приходит»:
- **Категория уведомления = серверная severity** события Frigate
  (`data.max_severity`: alert/detection), а не локальная эвристика
  «есть зоны и клип = alarm». События, которые Frigate не отнёс ни к
  alerts, ни к detections, больше не будят вовсе.
- **Снятие всех категорий в настройках реально глушит уведомления**
  (раньше пустое множество отключало фильтр целиком — «снял всё» = «всё включено»).
- **«Категории обзора по камерам» починены под схему Frigate 0.17**:
  раньше приложение писало `review.alerts: ["all"]` (невалидно, сервер
  отклонял/откатывал конфиг). Теперь — `review.alerts.enabled` /
  `review.detections.enabled` (bool) через `config/set` с `update_topic` —
  применяется на лету, без рестарта Frigate; `motion` = камерный
  `motion.enabled` с блокировкой недопустимой связки motion-off + detect-on.
- Сервис уведомлений сверяется с серверным review-конфигом камер
  (раз в 5 мин) — уведомления глушатся сразу, не дожидаясь рестарта Frigate.
- Чипы «камеры/классы»: снятие последнего больше не включает все;
  чип «Движение» из настроек уведомлений убран (motion-объектных событий нет).
- Тихие часы: проверка по времени события (не поллинга); «ч:ч–ч:ч» = круглосуточно.

## 2.1.1 (vc 22) — компактный календарь журнала
Ячейки даты с фиксированной высотой (30 dp), рендер только нужных недель,
плотнее строки списка: до нижней панели помещается ~11–12 строк журнала
(было ~4, на экранах с большой высотой список не влезал вовсе).

## 2.1.0 (vc 19) — журнал, псевдонимы камер, диагностика и защита от «тихих» падений
- **Диагностика (Diag)**: кольцевой буфер 500 записей через `Log.e` (переживает R8),
  native-safe маркеры с `fd.sync()` (переживают SIGSEGV), глобальный
  UncaughtExceptionHandler с дампом стека+буфера в `files/crash/`, маркер сессии
  и детекция «прошлый запуск завершился нештатно», onTrimMemory/onLowMemory.
  Трассировка всего пути «тап по миниатюре → экран → плеер».
- **Исправления кандидатов краха** (ревизия 16.11.2026): recover Keystore при
  повреждении EncryptedSharedPreferences (бросал в recomposition при первом тапе);
  фолбэк вместо rethrow в `MediaSources.okHttpDataSourceFactory`; `distinctBy(id)`
  при доклейке страниц Explore («Key already used»); `Uri.encode` сегментов
  маршрутов (имена камер/событий со спецсимволами); безопасный парсинг ключа дня
  в Архиве.
- **Журнал**: новый раздел — календарь событий; тап по дате — хронологический
  список «время · зафиксировано перемещение: субъект · камера», тап по строке — событие.
- **Псевдонимы камер**: отображаемое имя задаётся в Настройки → Камеры, хранится
  только в приложении (конфиг Frigate не меняется), применяется во всех экранах
  и в заголовках уведомлений.
Проверено на эмуляторе (API 36) с живым сервером Frigate 0.17.1: навигация,
плеер, журнал, псевдонимы; JVM-тесты зелёные.

## 2.0.3 (vc 18) — фикс краха при открытии камеры
Live-настройки `DefaultLoadControl` нарушали инвариант media3
(`minBufferMs 1500 < bufferForPlaybackAfterRebufferMs 2000`):
`ExoPlayer.Builder` кидал `IllegalArgumentException` на каждом тапе по камере —
приложение «сворачивалось на рабочий стол». `minBuffer` поднят до 2500 мс.
Проверено на живом сервере: камера открывается, поток идёт.

## 2.0.2 (vc 17) — гигиена релиза
R8 `assumenosideeffects`: `Log.v/d/i` вырезаются из release-кода
(warn/error остаются). Поведение не меняется.

## 2.0.1 (vc 16) — починена иконка приложения
Runtime-парсер VectorDrawable отбрасывает вектор целиком при эллиптических
дугах `A` с `rx≠ry` и ненулевым поворотом — лаунчер показывал дефолтную
заглушку. Эллипсы foreground/monochrome переведены на кубические Безье.
Также в 2.0.x: прод-подпись (CN=Homelab VSS) вместо debug-ключа, `keep.xml`
против вырезания launcher-ресурсов, отключён падающий lint-детектор
`NullSafeMutableLiveData` (known issue lifecycle 2.9.x).
